# Changelog

## Unreleased

- Fix: two defects from the batch-1 adversarial review. (1) The session approval cache seeded from a human **Always allow** reply is now keyed by the **root** session rather than the replied event's (subagent) session: `reviewer.handleReplied` resolves `session.root` before `cache.add`, matching the root-session key `dispatch` reads, so a subagent approval is actually reused instead of dead-seeding. A composed test seeds via the reviewer and proves `dispatch` reuses the entry without a model call. (2) `benchmarks/corpus.schema.json` is no longer decorative: the corpus test suite validates every `benchmarks/corpus/*.json` entry against the JSON Schema itself (a test-side interpreter for type/required/enum/additionalProperties/items/minItems/minLength, zero new dependencies) and cross-checks the hand-rolled TS mirror's enums and key sets against the schema so the two cannot drift silently; `validateCorpusEntry` now also enforces `additionalProperties: false`. 364 tests (was 359).
- Fix: a model-reviewed permission that loses opencode's headless auto-reject race is no longer dropped from the calibration log. opencode's `run` client auto-rejects `permission.asked` immediately — there is no grace window and no plugin hold/claim hook (the `permission.ask` hook declared in `@opencode-ai/plugin` is never triggered by the 1.19 server) — so a model review (~1 s+) loses the reply race. The reply is still correctly suppressed, but `dispatch.reviewAndReply` now writes the `decision` event before the abort check (and skips the session-approval cache for a permission that is already settled), so the completed review is recorded. Documented acceptance in the README: headless `opencode run` is not the plugin's primary environment; the TUI server is long-lived and has no auto-reject. `scripts/e2e-resume-check.sh` gains timing instrumentation (`date +%s%3N` around each run beside the plugin's per-decision `elapsedMs`) and a second, retried model-reviewed scenario asserting the `decision` event was written even though the reply lost the race. 359 tests (was 357).
- Feat: the session approval cache now learns user-originated **Always allow** replies from opencode's native permission UI. The `permission.v2.replied` / `permission.replied` handlers correlate the replied requestID with the original asked request, seed `cache.add(sessionID, action, always-patterns)` for human `always` approvals, and skip requestIDs the plugin answered itself (tracked in a Set before every `reply()` call). One-time (`once`) replies and shadow-mode decisions are never cached, and v2 `save` patterns are treated as the session-approval patterns. 315 tests (was 309).
- New in-repo calibration harness: a benchmark corpus (`benchmarks/corpus/*.json` + `benchmarks/corpus.schema.json`) spanning authorized security work, secrets-workflow-done-right, data movement, infra teardown, chaos engineering, repo surgery, known-vendor pipe-to-shell, and the gate-fixture meta-case, plus the mandatory `bad_looks_benign` adversarial complement (base64 id_rsa to a paste service, `history | sh`, `chmod -R 777 /`, DNS exfil via `dig`, token-in-URL), the `gh pr create` acceptance scenario (#18), and `.env`-in-prompt-text fixture cases. Level 1 `benchmarks/rater-bench.ts` calls `rateCommand` directly over the corpus (model matrix via `systemOneModel`, N repeat-runs, default 5) and emits per-signal mean/max/variance, ROC-style separation margins between the `benign_looks_bad` and `clearly_bad` masses, and threshold-sensitivity curves into `benchmarks/results/` (gitignored); it live-key gates and skips cleanly, and the pure helpers (`corpus-schema.ts`, `bench-stats.ts`, `bench-core.ts`) are unit-tested. Level 2 `benchmarks/agent-bench.sh` extends the `scripts/e2e-resume-check.sh` serve+attach pattern with a scratch shadow-mode root, its own diagnostics path, scenario-driven prompts, and a nothing-enforced assertion — user-run only. Zero new dependencies; 357 tests (was 315).
- Fix: fast-deny resumes now carry agent/model/variant routing. The fast-deny branch still replies immediately — before any context fetch, preserving the auto-reject race win — then derives routing lazily from a single `session.messages` call inside the fire-and-forget resume path, using the same precedence as the normal path (`latestUserRouting` first, `lastAssistantAgent` fallback, `{}` if neither). `session.root` is still never called on this path, and a failed/empty messages fetch falls back to `{}` without breaking the resume. This stops deterministic blocks switching a planner turn to the default builder and makes the `scripts/e2e-resume-check.sh` `routing.agent` gate consistent with the reply path. Zero new dependencies; 309 tests (was 307).
- Fix: deterministic denies now reply before opencode's headless auto-reject can win the race. New `policy.fastDeny({ action, resources })` evaluates only the two context-free deny codes (`catastrophic_delete`, `secret_exposure` — reusing `detectSecretExposure` and the extracted catastrophic-delete rule), and `dispatch.reviewAndReply` runs it at the very top, before `resolveRootSessionID`/`session.messages`. A fast-deny replies within a single event-loop tick with the same shadow-mode transformation (`shadow_` prefix + toast for the non-always-enforced `secret_exposure`; `catastrophic_delete` stays enforced in every mode) and writes the same `source: "policy"` decision event, so diagnostics are unchanged apart from latency. This removes 2–3 HTTP round-trips from every deterministic block in normal TUI use and stops the plugin losing the auto-reject race in unattended `opencode run`. Allow codes and the context-dependent prohibition scan are deliberately not fast-pathable. Fast-deny resumes derive routing from a lazy post-reply messages fetch (see above). Zero new dependencies; 307 tests (was 298).
- Docs: README documents `fastDeny` (context-free deny codes evaluated before any context fetch) and fast-deny resume routing in the serve+attach e2e section.

- Fix: resume-after-denial no longer fails silently. The opencode SDK's `Session.prompt()`/`promptAsync()` resolves to `{ data, error }` instead of throwing by default, so the previous `catch {}` never fired and a rejected resume prompt (e.g. session-busy/409) disappeared. `resumeSession` now inspects the result, retries once after a 750 ms delay, and writes a `resume` diagnostic event (`ok: true` with the winning `attempt`, or `ok: false` with a sanitized `JSON.stringify`-capped error detail) to the diagnostics JSONL. The default `resumeAfterDenial` closure now receives `config.diagnosticsPath`; the sleep is injectable for tests. Zero new dependencies.
- Fix: the resume prompt no longer fires while the rejected agent turn is still tearing down, and is now verified to have actually started. `resumeSession` polls `client.session.status` every 250 ms (injectable) for up to 10 s before each prompt attempt, logging every poll as a `resume_probe` event (`{ event, sessionID, attempt, result: "busy" | "idle" | "absent" | "error", error? }`). `session.status` only lists **active** sessions, so a missing entry means idle: an `absent` result is logged and then treated as idle, prompting immediately (`waitMs` ~0). A `busy` session keeps polling, and an errored status call (genuinely unknown, not idle) is retried within the budget; the wait only fails open at the timeout and flags the `resume` event `failOpen: true` (a client with no `session.status` method is treated as idle immediately). After a prompt is accepted, `started` is verified by polling `session.messages` (directory-scoped) up to 2 s for the injected `[Calibrated Access]` continuation message itself: `started: true` when it appears, `started: false` with `note: "prompt accepted but no turn started"` when the message list is fetchable but the message never appears, and `started` omitted entirely when the message list cannot be fetched. `started` is informational and never fails a resume. Zero new dependencies.
- Fix: continuation prompts are routed like a real user turn. New `context.latestUserRouting` reverse-scans the already-fetched raw messages for the latest **user** message (the routing carrier — not assistant messages), skipping synthetic `[Calibrated Access]` continuations, and extracts `agent`, `model` (`{ providerID, modelID }`, accepting a `{ providerID, id }` model too), and `variant` (from the model object). `dispatch` derives this routing from `rawMessages` and passes it to `resumeAfterDenial`; `reviewer` spreads `agent`/`model`/`variant` onto the prompt body, so a denied planner turn continues under the same agent/model/variant instead of silently switching to the default. `context.lastAssistantAgent` is retained as the fallback when no user message yields routing. The `resume` event logs the applied routing (`routing: { agent?, model?, variant? }`, names/ids only).
- Fix: session-scoped SDK calls are now directory-scoped, matching opencode's multi-project model. The plugin reads the legacy host's `input.directory` and threads it through `RuntimeContext.directory` to `session.get`, `session.messages`, `session.status`, and `session.promptAsync`/`session.prompt` as `query: { directory }` (omitted entirely when the host supplies no directory, preserving the old unscoped call shape). Without scoping, `session.status` returns another project's map so the session looks absent (which now reads as idle and can fire the continuation too early); with it, the probe history shows genuine `busy` → `idle` transitions and the continuation lands in the owning project.
- The user-run harness `scripts/e2e-resume-check.sh` (NOT part of `bun test`/CI) creates a temp dir with a fake `.env`, starts a long-lived `opencode serve` in the background on a free port (health-polled until ready), attaches one `opencode run --attach` asking the agent to print it (a deterministic secret-exposure block), waits ~12 s after the client exits for the server-side resume loop, then greps the diagnostics JSONL. The serve+attach shape is required because the resume loop lives in the server and dies with a short-lived `opencode run` process; PASS requires the newest `resume` event to have `ok: true` AND a `routing` object carrying an agent, and `started` is printed on its own `STARTED:true|false|null` line informationally.
- Docs: README documents the `resume_probe`/`resume` fields (`waitMs`, `failOpen`, `started`, `note`, `routing`), directory scoping, user-message routing, the absent-means-idle semantics, the message-based `started` verification, and the serve+attach user-run e2e script; 298 tests (was 261).
- Diagnostics `decision` events from a model review now carry the API's `usage`/`cost` fields (when present) alongside the signal map, turning the shadow-mode JSONL log into a spend ledger. Policy- and session-sourced decisions carry neither — no model call was made.
- New `scripts/sum-diagnostics.ts` (`bun run scripts/sum-diagnostics.ts <diagnostics.jsonl>`) plus pure aggregator `src/diagnostics-sum.ts`: totals decision events, model-reviewed count, input/output tokens, and USD — measured from the provider's `cost` when present, otherwise estimated at the published Jev input rate ($0.042/M) — with per-day and per-session breakdowns. Tolerates both token key shapes (`input_tokens`/`output_tokens` and `prompt_tokens`/`completion_tokens`), `cost: null`, and malformed lines (skipped and counted). Zero new dependencies.
- Docs: new README "Measure your actual spend" section with script usage and sample output; 257 tests (was 242).
- Capture optional `usage`/`cost` fields returned by the System One (`/systemone`) and chat-completions APIs and pass them through on `SignalScores` (`usage`/`cost`). Both are optional and never required — a live call is unaffected when the provider omits them.
- Integration test now prints the measured per-call `usage`/`cost` (soft-assert: warns if the live API returns none, never fails).
- Docs: README "Cost" section with per-rating and per-1,000 estimates for Options A/B (Jev) and C (gpt-4o-mini).

## 0.4.0 — 2026-11-06

- New deterministic secret-exposure detection (`detectSecretExposure`): blocks commands that would print, redirect, or transmit secrets — `echo $API_KEY`, `printenv GITHUB_TOKEN`, `env > creds.txt`, `printenv | curl`, `curl` auth headers/queries with `$VAR` secrets, git URLs with inline credentials, and secret vars piped or redirected. Detection is conservative: prose words like "token", flag names, and non-secret contexts (`grep token`, `ssh-keygen`, `printenv PATH`, `env | grep TERM`) are not blocked.
- Extends secret-exposure detection to secret-bearing files: stdout read utilities (`cat`, `head`, `tail`, `less`, `more`, `bat`, `grep`, `rg`, `awk`, `sed`, `strings`) on secret-file paths (`cat .env`, `less ~/.ssh/id_rsa`, `bat server.pem`) and `git add` of an explicit secret-file path (`git add .env`, `git add -f server.pem`) are denied. Sourcing (`. .env && cmd`, `source .env`), process-substitution consumption (`curl -K <(printf ... "$API_KEY")`), `cp`/`chmod`, non-secret file reads, and indiscriminate staging (`git add .`, `git add -A`) stay allowed.
- Denials now carry actionable, secret-free `alternatives` (`src/alternatives.ts`), surfaced in both the rejection message and the agent continuation message under a `Safer alternatives:` heading.
- Shadow mode now also applies to deterministic denies: secret-exposure denies are logged and allowed through. `catastrophic_delete` and `explicit_user_prohibition` remain enforced in every mode.
- New `user_prohibited` safety signal — the eighth: "Did the user explicitly or implicitly forbid this action in the conversation (prohibitions, exclusions, refusals, off-limits areas)?" Mirror of `user_requested`: model-scored by both providers, default thresholds 0.7/0.5, overridable via `signalThresholds`. Extra prompt contexts flag version-control staging that could include secret files the user excluded (`git add .`, `git add -A`, `git commit -a`, `git stash -u`) and declared off-limits areas; blocks carry staging-specific safer alternatives (stage files individually after confirming none are secret-bearing; run `git status` first and add only the intended paths).
- Fix: `sessionApprovals: false` now disables the session-approval cache entirely (no reads or writes); previously it had no effect.
- Fix: broadened explicit user-prohibition phrase matching in the deterministic policy gate — the gate that blocks commands the user prohibited in recent messages, enforced in every mode, now recognizes more prohibition phrasings.
- Fix: wired `resumeAfterDenial` to the session continuation — denials and reviewer failures now pass a continuation message (deny reason plus safer alternatives) to the agent so it can recover with a lower-risk step instead of stalling.
- Docs: README secret-exposure section; 227 tests.
- Docs: working GitHub install instructions, new Provider Options section (TypeSafe / existing OpenRouter key / OpenAI-compatible last resort), Verify your setup steps, and Development quickstart with Bun prerequisites, and documented `user_prohibited` as the eighth signal across README, opencode.jsonc.example, and AGENTS.md.

## 0.3.0 — 2026-11-03

- **Breaking:** removed `riskThresholdBash` and `riskThresholdDirectory`. The 2-axis alignment/impact risk matrix is replaced by seven calibrated safety signals: `destructive`, `secret_exposure`, `exfiltration`, `prompt_injection`, `scope_creep`, `user_requested`, `severity`.
- New `signalThresholds` option: per-signal `{ block, ask }` thresholds (0–1), merged over defaults.
- `user_requested` is a protective override signal — a high-probability explicit user request downgrades an `ask`-tier deny to allow; it never downgrades a `block`-tier deny.
- Fail-closed: when no risk signal reaches the 0.5 confidence floor, enforce mode denies with `no_confident_signals` (mirrors rater-failure default); `user_requested` cannot override it. Shadow mode logs/toasts it.
- New `mode` option: `"enforce"` (default) denies on signals; `"shadow"` never blocks, replying `once` while logging what enforcement would have done.
- Diagnostics `decision` events now include `mode` and the full `signals` probability/confidence map.
- Both providers (`typesafe`, `openai-compatible`) now evaluate all seven signals in a single pass.
- 144 tests (119 unit + 25 integration).

## 0.2.0 — 2026-11-03

- Pluggable model providers: new `provider` option (`"typesafe"` (default) or `"openai-compatible"`).
- Configurable System One endpoint via `systemOneBaseUrl` (default `https://api.typesafe.ai/v1`); `/systemone` appended automatically — works with TypeSafe native, OpenRouter Jev, and local clones (Kev, SemIf, NanoJev, Von).
- New options: `systemOneApiKey`, `systemOneModel`, `openaiApiKey`, `openaiModel`, `openaiBaseUrl`.
- Backward compatible: legacy `typesafeModel` / `typesafeApiKey` alias to the new `systemOne*` options; blank strings are treated as absent.
- OpenAI-compatible chat fallback for general LLMs when no System One model is available (not Jev-aligned; scores are less calibrated).
- Security hardening: 15s fetch timeout, API key redaction in error messages, runtime response validation with score clamping, prompt injection hardening in the OpenAI path.
- 133 tests (102 unit + 31 integration).
